# Remote Print Server

Independent coordination API for Remote Print Manager. This service stores device identity, pairing state, printer metadata and print-job metadata. It does **not** access Windows Spooler. In Phase 2 it transports only client-encrypted document envelopes through private Vercel Blob.

## Local setup

Vercel is pinned to Python 3.12. Use Python 3.12 locally for an identical runtime; Python 3.11 remains usable for the current test suite when 3.12 is not installed.

Vercel detects the FastAPI instance through `tool.vercel.entrypoint = "app.main:app"` in `pyproject.toml`. The `vercel.json` file configures only the `app/main.py` function duration and Cron; no catch-all rewrite or custom runtime string is required.

```powershell
cd "D:\ĐỒ ÁN WEBSITE\GITHUB\PRINTEXE\REMOTE_PRINT_SERVER"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
$env:ENROLLMENT_SECRET = "replace-with-a-long-random-secret"
.\.venv\Scripts\python.exe -m uvicorn api.index:app --reload
```

Health/readiness check: `GET http://127.0.0.1:8000/api/v1/health`. It executes `SELECT 1` and returns HTTP 503 with a generic database status when PostgreSQL is unavailable.

API docs are available at `/api/v1/docs` in development only.

## Device registration

Registration is an enrollment operation. The `X-Enrollment-Secret` header accepts either the administrator's server secret or a customer activation code generated by the Telegram bot. Customers only receive the time-limited activation code; they never receive `ENROLLMENT_SECRET`. The response contains a device token once; the server stores only its SHA-256 hash.

```powershell
$body = @{ deviceId = "client-01"; name = "Office Client"; role = "CLIENT"; appVersion = "1.0.0" } | ConvertTo-Json
$registered = Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/devices/register `
  -Headers @{ "X-Enrollment-Secret" = $env:ENROLLMENT_SECRET } `
  -ContentType "application/json" `
  -Body $body

$registered.deviceToken
```

For a customer device, replace `$env:ENROLLMENT_SECRET` with the one-time code received from the administrator. The code is stored only as a hash, can be limited to 1-15 devices, expires automatically, and can be revoked from Telegram. Re-registering the same device with the same code does not consume another device slot.

Use the token as `Authorization: Bearer <deviceToken>` for `/devices/me` and `/devices/heartbeat`. Keep it in the Windows client's protected local credential store; never commit or log it.

## Production rules

Set `RPM_SERVER_ENV=production`, an explicit PostgreSQL `DATABASE_URL`, a long random `ENROLLMENT_SECRET`, a separate `ADMIN_API_KEY`, and HTTPS-only `ALLOWED_ORIGINS`. Apply `migrations/001_initial.sql` through the database migration process before serving traffic.

For a new PostgreSQL database, run the migration once from a machine with `psql` access:

```powershell
$env:DATABASE_URL = "postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
psql $env:DATABASE_URL -f .\migrations\001_initial.sql
```

The application auto-creates schema only for local SQLite tests. Production PostgreSQL relies on the migration and does not run `create_all()` during a Vercel cold start.

Do not use `localhost` as a remote Host address. The server is only a coordination layer; a future Windows client integration must still prove the Host endpoint and authorization before declaring a connection successful.

## Current API surface

- `GET /api/v1/health`: service health without secrets.
- `POST /api/v1/devices/register`: enroll or rotate a device token.
- `GET /api/v1/devices/me`: return the authenticated device profile.
- `POST /api/v1/devices/heartbeat`: update the authenticated device's last-seen timestamp.
- `POST /api/v1/pairing-codes/issue`: issue one new 6-character code for an authenticated application session.
- `GET /api/v1/pairing-codes/current`: read the authenticated device's latest code status.
- `POST /api/v1/pairing-codes/resolve`: let an authenticated Client resolve a Host code into a pending pairing request.
- `POST /api/v1/pairing-codes/revoke`: revoke a code owned by the authenticated device.
- `GET /api/v1/internal/cleanup`: protected Vercel Cron endpoint; requires `Authorization: Bearer $CRON_SECRET`.
- `GET /api/v1/jobs`: Host-only queue polling with an optional status filter and limit.
- `GET /api/v1/jobs/{jobId}`: Client or owning Host reads job state.
- `POST /api/v1/jobs/{jobId}/claim`: atomically leases a queued job to a Host and returns a one-time claim token.
- `POST /api/v1/jobs/{jobId}/renew`: renews an active Host lease.
- `POST /api/v1/jobs/{jobId}/ack`: acknowledges that the Host accepted the claimed job.
- `PATCH /api/v1/jobs/{jobId}/status`: advances a claimed job through the guarded spooler state machine.
- `POST /api/v1/jobs/{jobId}/cancel`: cancels a queued or claimed job without touching the Windows spooler.
- `PUT /api/v1/jobs/{jobId}/document`: Client-only multipart upload of an already encrypted document to private Vercel Blob.
- `GET /api/v1/jobs/{jobId}/document`: Host-only download after a valid claim; returns ciphertext bytes, not JSON.

Pairing codes use only `A-Z` and `0-9`, are generated with a cryptographically secure source, expire after `PAIRING_TTL_MINUTES`, and are never reused. The database stores a unique hash and encrypted value; the plaintext is returned only to the authenticated owner when issuing or reading its own current code.

## Vercel production variables

Required in the `Production` environment:

- `RPM_SERVER_ENV=production`
- `DATABASE_URL=<PostgreSQL connection URL>`
- `ENROLLMENT_SECRET=<long random secret>`
- `ADMIN_API_KEY=<separate long random secret>`
- `CRON_SECRET=<separate long random secret>`
- `ALLOWED_ORIGINS=https://<allowed-frontend-origin>`
- `BLOB_STORE_ID=<private Vercel Blob store id>` or `BLOB_READ_WRITE_TOKEN=<private Vercel Blob token>`
- `MAX_DOCUMENT_BYTES=4194304`

Optional values use the source defaults: `PAIRING_TTL_MINUTES=10`, `MAX_PAIRING_ATTEMPTS=5`, `HEARTBEAT_TIMEOUT_SECONDS=120`, `RATE_LIMIT_WINDOW_SECONDS=900`, and `RATE_LIMIT_MAX_ATTEMPTS=10`.

Pairing, printer permissions, print-job coordination, release metadata, and production deployment are intentionally separate slices and are not claimed complete yet.

### Print-job delivery contract

The coordination API stores metadata and a private `dataRef`. The Client sends only an AES-256-GCM envelope to the multipart endpoint; the Server never receives the plaintext or document key. A Host must claim before downloading and must retain the claim token for every acknowledgement or status update. The allowed state path is:

`QUEUED -> CLAIMED -> DOWNLOADING -> SPOOLING -> SPOOLER_ACCEPTED -> COMPLETED`

Failure may transition to `FAILED` or `UNKNOWN`. An `UNKNOWN` result must be reconciled before any retry so a document is not printed twice. `Idempotency-Key` is unique and is reused for network retries of the same client print intent.

The current safe upload limit is `MAX_DOCUMENT_BYTES=4194304` (4 MiB), below the Vercel request limit. Larger documents remain rejected until a future presigned/multipart client-upload path is implemented.

## Retention policy

Vercel Cron calls cleanup daily at `02:00 UTC`. Cleanup only removes terminal rejected/expired pairings, terminal print jobs whose `updated_at` is older than 72 hours, old audit events, and old rate-limit events. Devices, approved pairings, printers, active/expired pairing-code history, unfinished jobs, and idempotency records are retained. Cleanup runs are retained for 30 days.
## Telegram admin bot

The optional Telegram bot is a webhook-based admin interface. It does not expose
the enrollment secret to customers. Configure these Production variables:

```text
TELEGRAM_BOT_TOKEN=<BotFather token>
TELEGRAM_ADMIN_IDS=<comma-separated numeric Telegram user IDs>
TELEGRAM_WEBHOOK_SECRET=<random webhook secret>
```

Apply `migrations/005_customer_activation_codes.sql` and `migrations/006_activation_code_device_binding.sql` before using `/create-code` or customer activation. Migration 006 binds each registered device to the code used for activation.
The bot endpoint is `/api/v1/internal/telegram/webhook` and supports:

```text
/help
/create-code [label] [days] [max_devices]
/list-codes
/revoke-code CODE
```

Set the Telegram webhook after the Vercel deployment using the Bot API, passing
`TELEGRAM_WEBHOOK_SECRET` as the `secret_token` header value. Keep the bot token
and webhook secret out of source control and never send them in chat.
